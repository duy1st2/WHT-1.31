# WHT_Lib and Fast Jass library loader

Actual reference: WHT/native/runtime.cpp ProcessLoadDllAndMpq (WHT_Lib nonrecursive scan, FastJass-name gating, root FastJass.dll), and #fastjass/#fj. WHT-1.29 has only stored Fast Jass config; user scope permits actual WHT implementation. Reference SHA256 and pre-edit backups recorded before changes in wht-library-evidence.json.

Both 1.31 dispatchers now accept #fastjass/#fj [0|1|off|on|false|true], bare command toggles. Strict parser rejects unknown/extra arguments and controls. Setting is saved and reloaded/confirmed before rescanning. Success reports actual newly loaded DLL/archive counts, already loaded counts, and whether any FastJass DLL is loaded. Missing optional binary does not imply an acceleration implementation exists. OFF reports that previously loaded FastJass modules remain until game restart.

Nonrecursive WHT_Lib scan selects .dll/.mpq/.mix case-insensitively, deterministic path order; root FastJass.dll loads after library DLLs for dependency order. DLLs use existing CompatibleDll131 machine/optional-header/DLL-flag validation and DllLoader131. Archive providers use existing four-profile MPQ loader; its optional priority argument retains manual default10 and uses library priority30 onward. Existing manually mounted providers retain their priority, avoiding remount. DLL and archive cache maps are shared with manual commands; no duplicate LoadLibrary references or repeated mounts. Module/provider lifetime remains process-long like WHT.

DLL startup runs once at authorized Local menu/UI startup before an active match is required. Archive startup runs once at the existing native-ready asset/UI stage. No per-frame directory scans. #fj invocation explicitly rescans, allowing new files or failure retries; reentrant library initialization cannot save or start another scan. No game native RVAs/guards added or changed, new hooks, threads, frames or INI keys. Only WHT-1.31 changed; current user clients not stopped.

Integration tests use isolated owned runtime-test subdirectories and real x86/x64 fixture DLLs, verify callable exports, FastJass filtering, architecture/invalid-PE rejection, no recursive scan, root dependency order, shared dedup, phased startup once, archive priority, empty optional directories, failures and actual INI persistence/reload. Fixture modules are released in the test process, and only the verified dedicated test directory is removed. Archive mounting uses an injected backend in these tests; existing MPQ native-ABI tests additionally verify priority30 on the same verified x86/Win64 calling convention. No third-party FastJass binary bundled or run, and no in-game JASS/FPS improvement measured.
